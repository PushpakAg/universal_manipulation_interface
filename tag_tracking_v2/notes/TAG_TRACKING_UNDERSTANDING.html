1. What the pipeline does

UMI records a person using handheld grippers. The original gets gripper poses from wrist-camera SLAM. This fork uses tag tracking instead.

  • A head GoPro watches an ArUco cube on each gripper (70 mm cube, four 60 mm tags).
  • Environment tags on the table and walls give the world frame (one is the origin). Two dock tags mark where grippers rest between episodes.
  • Wrist GoPros give the gripper video, an IMU, and a view of the environment tags.
  • GTSAM fuses head-tracked cube poses, the head IMU, and each wrist IMU plus wrist-seen tags into one pose per frame.
  • A continuous take is cut into episodes between dock periods; docking is trimmed and wrist clocks are synchronized to the head from motion.
Original GoPro MP4s (head, left, right)→run_tag_tracking_pipeline.py→dataset_plan.pkl→MCAP per episode→Odyssey delivery (optional)

4. Time synchronization

  1. Audio sync (06a): coarse head-to-wrist offset.
  2. Motion sync (03s): each wrist IMU is fitted to its cube's rotation as tracked by the head. Gives a per-episode correction, a drift line and an accuracy in wrist_sync.json.
  3. The wrist video is placed with that imu_time_offset.
  4. Check: check_frame_sync.py compares each wrist camera's orientation from its own environment tags with the head cube orientation, with no IMU. One frame is 16.7 ms.

5. Output formats

MCAP per episode (robot0 right, robot1 left; camera0 robot0 wrist, camera1 robot1 wrist, camera2 head):

TopicContent
robot{i}/eef/state, eef/poseTCP pose, world frame
robot{i}/gripper/stateGripper width (m)
robot{i}/imu, /head/imuCamera IMUs
/cameras/camera{j}/videoH.265 from the GoPro files, not re-encoded
/head/poseHead camera pose in the world

Each camera video starts at its own keyframe, so the three can start up to 1 s apart. With --keep_gaps the plan is not usable for the replay buffer. A task ends when the first gripper returns to the dock.

7. What the Odyssey delivery needs

Spec v0.6, container mcap. 13_export_delivery.py -i <session> -c <config> -d <delivery.yaml> -o <delivery_dir> -j 16 (needs pyarrow).

Inputs

  1. A processed session with dataset_plan.pkl (the --keep_gaps plan).
  2. The session's tag tracking config.
  3. A filled copy of example/tag_tracking/delivery.yaml. Anything left null is exported as null.
  4. Optionally annotations (08_annotate_episodes.py, 09_normalize_labels.py). They call the Anthropic API and need the anthropic package and ANTHROPIC_API_KEY. Without them: no annotations.json, outcome unknown, success null.

What only the recording team can supply

LevelFields
delivery:vendor_name, dataset_name, delivery_id, robot_model, gripper_type, source_uri_prefix, license_reference, anonymization_state (faces_blurred | not_required | pending | other), consent_reference
per sessiontask_text, task_family, object_tags, collection_mode (scripted | freeform | adversarial | in_the_wild), scene_tags, environment_id, operator_id, station_id, consent_reference

Output per episode

FileContent

episode.jsonIds, UTC start / end, frame rate, clock_sync_accuracy_ns, world frame, gripper range, task

episode_id = head serial + UTC start of the head video + head frame of the episode start, stable across re-exports. Lost tracking stays as null pose with pose_valid false; nothing is filled in.

9. Open items and gotchas

Quality report crash. umi/tag_tracking/quality.py:266 compares against accuracy_ms, which is null in wrist_sync.json for 4 of 7 head videos. Needs a decision on what status unknown accuracy gets. Image statistics are cached. Warnings seen before the crash: all videos 59.94 Hz ("not an integer rate"); the right wrist of the 13.49.41 recording has 14 skipped frames.
  • Sync: episode 20 unmeasured; episode 16 right wrist +10.2 ms.
  • 29 vs 28 episodes: annotation dry run covers 29 episodes with a task interval, the plan has 28. Not explained.
  • Validation status: 13_export_delivery.py says not_run; 11_check_quality.py says delivery takes it from quality.json. Not verified which holds.
  • Annotations need an API key and send frames to the Anthropic API. Review the dry-run frame sheets first.
  • tool_handling stopped at imu: its right-wrist calibration clip came from camera C3501325427851, which is in no config.
  • Test bug: tests/test_setup_calibration.py uses a missing executor fixture.
  • macOS arm64: av==10 has no wheel (used 12.x); numcodecs pin fails to build; only opencv-contrib-python==4.7.0.72 has the aruco API; AWS SSO tokens expire mid-download and aws s3 sync resumes.
