7. Findings

  1. ORIG and V2 are identical (28/28 byte-for-byte). Either can be the delivery source.
  2. S3 is not identical to ORIG/V2 in any of its 27 files. Same recordings, same video, same structure; different tracking/sync output (offsets up to 0.020 ms, poses up to 32.9 mm / 2.35°, gripper width up to 4.2 mm). S3 looks like an earlier run (uploaded 2026-11-21, before ORIG was written 2026-11-22).
  3. episode_000016 is not in S3 (listing confirmed with aws s3 ls: 27 objects). It exists locally in ORIG and V2 (identical).
  4. Pose gaps differ for robot1 in episodes 10, 13, 17: S3 has 48 / 38 / 62 pose steps missing vs 45 / 20 / 31 in ORIG/V2. ORIG/V2 also have gaps in episode 16 (710 steps, 7.7% of the episode).
  5. PRD U2 “same time span” is not met in any episode: the three video streams start up to 945 ms apart (limit 1 frame = 16.7 ms) and end up to 21 ms apart. Timestamps are on one common clock, so the content is aligned, but the PRD asks for each recording trimmed to the span all three views share.
  6. Sync-frame field meaning: the PRD asks for “the frame index of the sync event in each file”. The MCAP carries camera*_sync_frame = start frame in the source video, which is out of range for the delivered stream in most episodes. Document this for the client or add a stream-relative index.
  7. Pipeline flag: the V2 run summary logged “wrist sync accuracy 12.3 ms is above 8.3 ms”. Largest applied wrist offset in the files is 15.8 ms (episode 18); residual σ is ≤0.5 ms everywhere.
  8. Episodes 0, 1: one gripper barely moves (width range < 2 cm); allowed by PRD U5 as a passive role.
